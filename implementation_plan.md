# Development Roadmap: Candidex (Job Application Tracker)

This document outlines the end-to-end technical plan to build the "Manual-First, AI-Optional" Chrome extension. It defines the modern technology stack, required configurations, and a phased execution strategy.

---

## 1. Technology Stack

Given the requirements (Chrome Extension Manifest V3, no backend, premium UI, future AI), the following stack is recommended:

| Category | Technology | Why we chose it |
|---|---|---|
| **Core Framework** | Angular 18+ (Zoneless) | Opinionated architecture, perfect for DI (Google Sheets Service), highly performant with Signals. |
| **Bundler** | Angular CLI | Standard Angular tooling, configured to output for Chrome Extension environments. |
| **Styling** | Tailwind CSS v3/v4 | Rapid utility-first styling. Ensures a consistent, premium design system without bloat. |
| **Icons** | Lucide React | Clean, professional, open-source SVG icon library. |
| **Data & Auth** | Google Sheets API v4 | The sole data store. Uses Chrome's `identity` API for frictionless OAuth 2.0. |
| **AI (Phase 2)** | Puter.js | Backend-free, user-pays model for multimodal AI (vision models) and OCR. |

---

## 2. Brand & Styling Configuration

Based on the finalized `BRANDING.md`, the UI must adhere strictly to these constraints to ensure a premium, modern SaaS feel:

- **Typography:**
  - Headings & Numbers: `Plus Jakarta Sans` (for an ultra-modern geometric feel).
  - Body & UI Text: `Inter` (for maximum legibility at small extension sizes).
- **Color Palette (Tailwind):**
  - **Primary:** Indigo (`bg-indigo-600`) - Used for primary actions and active states.
  - **Neutrals:** Slate (`bg-slate-50`, `text-slate-900`) - Used for backgrounds and text.
  - **AI Highlights:** Amber (`bg-amber-100`, `text-amber-800`) - Exclusively used to tag data pre-filled by the AI.
  - **Status Tags:** Emerald (Offer), Blue (Interview), Amber (Applied), Rose (Rejected).

## 2. Required Configurations (Pre-requisites)

Before writing the application logic, specific external configurations must be established.

### 2.1 Google Cloud Platform (GCP) Setup
Since the extension talks directly to the user's Google Drive/Sheets, you must configure a GCP project:
1. Create a new project in the [Google Cloud Console](https://console.cloud.google.com/).
2. Enable the **Google Sheets API** and **Google Drive API**.
3. Configure the **OAuth Consent Screen** (set to "External").
4. Create **OAuth 2.0 Client IDs** for a "Chrome App/Extension".
   - You will need your extension's ID (generated by Chrome when you load the unpacked extension).
5. **Scopes required:**
   - `https://www.googleapis.com/auth/spreadsheets`
   - `https://www.googleapis.com/auth/drive.file` (to create the tracker sheet if it doesn't exist).

### 2.2 Chrome Extension Manifest V3 (`manifest.json`)
The manifest will require specific permissions to function:
```json
{
  "manifest_version": 3,
  "name": "Candidex",
  "version": "1.0.0",
  "action": { "default_popup": "index.html" },
  "permissions": [
    "identity",        // For Google OAuth
    "storage",         // For saving user preferences (e.g. skip notes step)
    "activeTab"        // Phase 2: For taking screenshots
  ],
  "oauth2": {
    "client_id": "YOUR_GCP_CLIENT_ID.apps.googleusercontent.com",
    "scopes": ["https://www.googleapis.com/auth/spreadsheets"]
  },
  "background": {
    "service_worker": "src/background.js",
    "type": "module"
  }
}
```

## 3. Development Phases

The project will be built in four strict phases, honoring the "Manual-first" rule.

### Phase 1: Foundation & Scaffold (Angular Chrome Extension Setup)
**Goal:** A working Angular Chrome extension shell configured with Tailwind and Zoneless change detection.

1. **Initialize Project:**
   ```bash
   ng new candidex --standalone --routing --style=scss --skip-tests
   cd candidex
   ```
2. **Enable Zoneless (Angular 18+):**
   Update `src/app/app.config.ts` to replace `provideZoneChangeDetection()` with the experimental zoneless provider:
   ```typescript
   import { ApplicationConfig, provideExperimentalZonelessChangeDetection } from '@angular/core';
   export const appConfig: ApplicationConfig = {
     providers: [provideExperimentalZonelessChangeDetection(), provideRouter(routes)]
   };
   ```
3. **Install Tailwind CSS & Lucide Icons:**
   ```bash
   npm install -D tailwindcss postcss autoprefixer
   npx tailwindcss init
   npm install lucide-angular
   ```
   *Configure `tailwind.config.js` to scan `src/**/*.html` and `src/**/*.ts`, and import Tailwind in `styles.scss`.*
4. **Extension Configuration (`angular.json`):**
   Chrome extensions cannot handle dynamic file hashing for the main entry points (like `manifest.json` or `background.js`). Update `angular.json`:
   - Set `"outputHashing": "none"` under the `build.options` and `build.configurations.production`.
   - Add `"src/manifest.json"` and `"src/background.js"` to the `"assets"` array.
5. **Build the Layout Shell:** Create the main responsive container component (the slide-out style panel) and set up routing using Angular **Signals** for state management.

### Phase 2: The Data Layer (Google Sheets)
**Goal:** Authentication and CRUD operations to the user's Sheet.

1. **Auth Flow:** Implement `chrome.identity.getAuthToken({ interactive: true })` to get the user's access token.
2. **Sheet Initialization:** Write a function that checks if "Job Tracker DB" exists in their Drive. If not, create it and write the header row based on the Schema defined in `PROJECT.md`.
3. **API Wrappers:** Write generic functions for:
   - `fetchApplications()`: Reads the sheet, parses rows into JSON objects.
   - `appendApplication(data)`: Appends a new row to the sheet.
   - `updateApplication(id, updates)`: Finds a row by ID and updates its status/notes.

### Phase 3: Path A — The Manual UI (v1 Launch)
**Goal:** A fully functional, premium manual tracking experience.

1. **Dashboard Component:** Build the stats overview and the list of recent applications.
2. **Applying Component:** Build the manual entry form (Role, Company, Platform, Links). Ensure validation requires the `company` field. Wire the submit button to `appendApplication()`.
3. **Response Tracking Component:** 
   - Build the search/filter UI (search by company/role).
   - Build the dropdown to change status (Interview, Rejected, Offer).
   - Show conditional `interview_date` input if "Interview" is selected.
   - Wire the save action to `updateApplication()`.
4. **Visual Polish:** Add loading skeletons, success toasts, and ensure the UI looks premium (animations, spacing, typography). *Reserve space (grayed out camera icon) for Phase 4.*

### Phase 4: Path B — The AI Extension (Future Phase)
**Goal:** Add Puter.js screenshot-assist without breaking Path A.

1. **Background Worker Setup:** Implement `chrome.tabs.captureVisibleTab` in `background.js` and set up the message listener.
2. **Puter.js Integration:** Install `@heyputer/puter.js` via NPM. Implement the authentication gate (`puter.auth.signIn()`) on first click.
3. **Intent Picker UI (Step 0):** Build the modal overlay asking "Job Post" or "Email Reply".
4. **AI Extraction Module:** Write the specific prompts detailed in the Feasibility Report and wire them to `puter.ai.chat()`.
5. **Multi-step Form Flow (Steps 1-3):**
   - **Step 1:** Render the form with AI-populated fields highlighted in amber.
   - **Step 2:** Conditionally render the "Fill Missing Fields" step if any nulls exist.
   - **Step 3:** Render the Notes step with the `chrome.storage.local` powered "Don't show again" checkbox.
